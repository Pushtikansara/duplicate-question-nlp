Part 1: Why Cross Encoder Exists

The Problem: Semantic Similarity

You have two questions:

Q1: "What is Artificial Intelligence?"
Q2: "Explain AI."

A human instantly knows these are duplicates. They ask the same thing. But to a computer, these are just strings of characters. Lexical similarity gives zero. Semantic similarity — the meaning — is high.

Bi-Encoder: The First Solution

Two identical transformers run independently:

Q1 → Transformer → Vector A (768-dim)
Q2 → Transformer → Vector B (768-dim)
Similarity = cosine(A, B)

Why invented: Scalability. Encode 10M questions once, compare new query against all with FAISS.

What it cannot solve: The two questions never see each other. "Explain" never knows "What is" expresses the same intent.

Why Cosine Similarity Fails

  • Homonyms: "What is Python?" — snake vs language. Same vector.
  • Negation: "enable" vs "disable" notifications — similar vectors, opposite meanings.
  • Fine-grained: "GPU for gaming" vs "GPU for deep learning" — different intent.

Cross-Encoder: The Precision Solution

[CLS] What is AI? [SEP] Explain AI. [SEP]
                    ↓
              One Transformer
                    ↓
           Classification Head
                    ↓
           Probability: 0.97

Why invented: Bi-Encoder loses cross-text interaction. Cross-Encoder allows every word in Q1 to attend to every word in Q2.

Comparison

PropertyBi-EncoderCross-Encoder
AccuracyGoodExcellent
Speed per pair~1ms10-100ms
ScalabilityBillion-scaleThousand-scale
Cross-attentionNoYes

In your project, the Cross-Encoder serves as the reranker.

Part 2: Transformers Recap

A Cross-Encoder IS a Transformer with a classification head. The "cross-encoding" comes from input formatting.

2.1 Embedding Layer

Embedding Matrix: [vocab_size x hidden_dim] = [128000 x 768]

A lookup table — the only place where tokens become vectors.

2.2 Tokenization

"What is Artificial Intelligence?"
    ↓ SentencePiece
[2054, 2003, 19204, 1385, 1029]

DeBERTa-v3 uses SentencePiece (vocab: ~128,000).

2.3 Special Tokens

TokenDeBERTa IDPurpose
[CLS]1Classification — aggregates sequence info
[SEP]2Separates sentences
[PAD]0Padding to max length

2.4 Position Embeddings

DeBERTa uses relative position (disentangled attention). The model knows how far apart tokens are, not just absolute positions.

2.5 Attention (Single Head)

Attention(Q, K, V) = softmax(Q x K^T / √d_k) x V

Q = X x W_Q  (Query: what is this token looking for?)
K = X x W_K  (Key: what information does this token have?)
V = X x W_V  (Value: the actual information to pass along)

"Explain" in Q2 attends to "What is" in Q1 → this is why Cross-Encoder works.

2.6 Multi-Head Attention

DeBERTa-v3-base: 12 heads, each with d_k=64. Each head specializes:

  • Head 2: Semantic similarity ("Explain" ↔ "What is")
  • Head 3: Abbreviation recognition ("AI" ↔ "Artificial Intelligence")
  • Head 4: Negation detection

2.7 Feed-Forward + Residual + LayerNorm

FFN(x) = GELU(x x W1 + b1) x W2 + b2   [768 → 3072 → 768]
output = LayerNorm(x + Attention(x))
output = LayerNorm(output + FFN(output))

2.8 Encoder Stack

Layer 0: Embedding → Layers 1-12: Attention + FFN + Residual + LayerNorm

  • Early: Surface patterns, local syntax
  • Middle: Semantic roles
  • Late: High-level meaning, cross-sentence relationships

Part 5: Attention Mathematics

Step 1: Create Q, K, V

Q = X x W_Q    [18x768] x [768x64] = [18x64]
K = X x W_K    [18x768] x [768x64] = [18x64]
V = X x W_V    [18x768] x [768x64] = [18x64]

Step 2-5: Score, Scale, Mask, Softmax

Scores = Q x K^T / √64         [18x18]
Scores[mask==0] = -inf          (ignore padding)
Weights = softmax(Scores, dim=1)  (each row sums to 1)

Step 6: Weighted Sum

Context_i = Σ_j Weights[i][j] x V[j]

Concrete: Attention from "explain"

TokenWeightMeaning
"what"0.15Matches intent
"is"0.12
"explain" (self)0.20Self-attention
"ai"0.10Topic recognition
"artificial"+"intelligence"0.16Abbreviation match

Through 12 layers: [CLS] encodes the full relationship.

Part 6: Why Cross Encoder is Different

Bi-Encoder

Q1 → Transformer → [CLS]_1 = f(Q1)   — knows NOTHING about Q2
Q2 → Transformer → [CLS]_2 = f(Q2)   — knows NOTHING about Q1
Similarity = cosine([CLS]_1, [CLS]_2)

Cross-Encoder

[CLS] Q1 [SEP] Q2 [SEP] → Transformer → [CLS]_joint
[CLS] attends to ALL tokens from BOTH questions
[CLS]_joint = f(Q1, Q2) — encodes the RELATIONSHIP

Two-Stage Architecture

Stage 1 (Bi-Encoder): 10M docs → FAISS → 100 candidates
Stage 2 (Cross-Encoder): Rerank 100 candidates → top-10

Your project uses this exact pattern: E5/BGE/MPNet retrieve, Cross-Encoder reranks.

Part 7: The [CLS] Token

[CLS] is a special token at position 0. Initially a random vector. Through training, it learns to aggregate information via attention.

Flow Through Layers

Layer 1:   [CLS] nearby attention → local syntax
Layer 2-3: [CLS] attends entities → "AI", "Artificial Intelligence"
Layer 4-6: [CLS] attends intent words → "What is", "Explain"
Layer 7-9: [CLS] cross-sentence relationships
Layer 10-12: [CLS] refines → final classification features

Why [CLS] Not Mean Pooling

  • Selective: [CLS] learns to emphasize task-relevant words
  • Relationship encoding: Captures cross-question intent matching
  • No dilution: Mean pooling dilutes the "AI"↔"Artificial Intelligence" signal

Part 8: Classification Head

[CLS] [768]
  ↓
Dropout(p=0.1)
  ↓
Linear(768 → 2): logits = x W^T + b
  ↓
Softmax → [p_non, p_dup]
  ↓
predicted = argmax → 0 or 1
prob_dup >= threshold → binary prediction

Softmax Example

logits = [-3.2, 1.8]
softmax[0] = exp(-3.2) / (exp(-3.2) + exp(1.8)) = 0.0067
softmax[1] = exp(1.8) / (exp(-3.2) + exp(1.8)) = 0.9933

Threshold Tuning

for thresh in np.linspace(0.1, 0.9, 81):
    preds = (probs >= thresh).astype(int)
    f1 = f1_score(true_labels, preds)
    if f1 > best_f1: best_f1 = f1; best_thresh = thresh

How Weights Update

Gradient flows through all 12 layers + embedding + classification head. Each of the ~184M parameters gets an AdamW update. The classification head (randomly initialized) learns fastest.

Why Each Hyperparameter Matters

  • max_length=128: Quora avg ~40 tokens. Too small → truncation. Too large → 4x GPU memory.
  • batch_size=16: Small → noisy gradients. Large → sharp minima.
  • lr=2e-5: Pre-trained DeBERTa needs small updates. 5e-4 destroys knowledge.
  • weight_decay=0.01: L2 regularization. Prevents overfitting.

Why Preprocessing Matters

  • Abbreviation expansion: "AI" → "AI (Artificial Intelligence)". Lets model match "AI" to "Artificial Intelligence". Without it: model sees different tokens.
  • Typo fixing: "artifical" → "artificial". Without it: subword fragmentation.
  • Consistency: Training and inference must use identical preprocessing.

Part 12: Common Mistakes

Impact Summary

MistakeImpactWhy
Overfitting-5% F1Memorizes, does not generalize
Threshold on test+1-2% F1 (optimistic)Leaks test info into decision
Data leakage+5-10% F1 (optimistic)Model sees test during training
Wrong preprocessing-10-20% F1Token distributions mismatch
Wrong tokenizerModel breaksDifferent vocabulary
Wrong checkpoint-3-10% F1Uses pre-trained not fine-tuned
No model.eval()-1-3% F1Dropout randomness during inference

Key Rules

  • Never tune threshold on test set — use validation
  • Always use identical preprocessing in training and inference
  • Always load fine-tuned checkpoint, not base model
  • Always call model.eval() + torch.no_grad() for inference

Part 13: Advanced Topics

Layer-wise Learning Rate Decay

Embedding:     lr x 0.1   (almost frozen)
Layers 1-6:    lr x 0.5   (syntax)
Layers 7-11:   lr x 0.9   (task-specific)
Layer 12:      lr x 1.0   (fine-tune)
Classifier:    lr x 10.0  (random init, needs fast learning)

Mixed Precision (FP16)

40% less memory, 2-3x speedup. Uses GradScaler to prevent underflow (gradients < 6e-8 become 0 in FP16).

Gradient Checkpointing

50% memory reduction at 20% speed cost. Recomputed activations during backward instead of storing them.

EMA (Exponential Moving Average)

shadow = decay * shadow + (1-decay) * weights. Smooths trajectory, finds flatter minima. +0.5-1% F1.

Temperature Scaling

softmax(logits / T)   T=1: default
T>1: softer (less confident)
T<1: sharper (more confident)

Label Smoothing

Label 1 → [0.05, 0.95] instead of [0, 1]. Prevents overconfidence. +0.5-1% F1.

Hard Negative Mining

Strategies: BM25 top-100 non-duplicates, Bi-Encoder high-similarity non-duplicates, model mistakes. Without hard negatives, model cheats with word overlap.

Knowledge Distillation

Teacher (DeBERTa-v3-large, 304M) → Student (MiniLM-L6, 80M). Loss = CE(student, label) + KL(student/T, teacher/T). Soft labels contain more information.

Technique Selection Guide

TechniqueWhenGain
Layer-wise LRFine-tuning large models+1-2% F1
Mixed precisionGPU with Tensor Cores2x speed

The tokenizer(q1, q2) call creates [CLS] q1 [SEP] q2 [SEP] format. squeeze(0) removes batch dimension. If removed, DataLoader creates [batch, 1, 128] instead of [batch, 128].

Critical: normalize_question with expand_abbrevs=True. Without it, "AI" and "Artificial Intelligence" would have different token IDs. Expect 2-5% F1 drop.

Pre-tokenization (Lines 200-233)

train_input_ids = []
for i in range(len(train_dataset)):
    train_input_ids.append(train_dataset[i]["input_ids"])
train_tensor_dataset = TensorDataset(torch.stack(train_input_ids), ...)

Pre-tokenizes ALL data into GPU memory. Without this: each epoch re-tokenizes 200k pairs (CPU bottleneck). Training 2-3x slower.

GPU Optimizations (Lines 184-188)

torch.backends.cudnn.benchmark = True
torch.backends.cuda.matmul.allow_tf32 = True

cudnn.benchmark: auto-tunes convolution algorithms. TF32: 19-bit precision on Ampere GPUs. Without: 20-40% slower.

Class-Weighted Loss (Lines 271-278)

weight_pos = n_neg / n_pos    # e.g., 1.70
class_weights = torch.tensor([1.0, weight_pos])
loss_fn = CrossEntropyLoss(weight=class_weights)

Counters class imbalance. Errors on duplicate pairs penalized 1.7x more. Without: model biased toward majority class.

Training Loop (Lines 322-367)

for epoch in range(num_epochs):
    for step, batch in enumerate(train_loader):
        loss = loss_fn(outputs.logits, labels) / gradient_accumulation_steps
        loss.backward()
        if (step + 1) % gradient_accumulation_steps == 0:
            clip_grad_norm_(1.0)    # prevents gradient explosion
            optimizer.step()
            scheduler.step()
            optimizer.zero_grad()

Gradient clipping at 1.0: if gradient norm > 1.0, scale down. Without: one bad batch can destabilize training. gradient_accumulation simulates larger batch size.

Validation (Lines 380-418)

model.eval()       # disable dropout
with torch.no_grad():    # no gradient computation
    probs = torch.softmax(outputs.logits, dim=1)

model.eval(): Without it, dropout active → different results each run. torch.no_grad(): Without it, 2x memory usage for computation graph.

Model Saving (Lines 421-431)

if val_f1 > best_val_f1:
    model.save_pretrained(output_path)
    tokenizer.save_pretrained(output_path)

Saves only when validation F1 improves. The tokenizer must be saved alongside the model for inference to work.

Test Evaluation (Lines 483-498)

for thresh in np.linspace(0.1, 0.9, 81):
    preds = (np.array(test_probs) >= thresh).astype(int)
    f1 = f1_score(test_labels, preds)

Finds threshold that maximizes F1 on test set. Note: This leaks test information. For strict evaluation, tune threshold on validation set and evaluate once on test.
